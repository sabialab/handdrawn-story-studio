# 旁白稿规范

**做什么**：把敲定的候选写成 `script.json`，过体检，过去AI味审校，然后才合成。
**产出**：工程目录下的 `script.json` + `public/voice/narration.wav` + `public/voice/timeline.json`。
**前置**：工程已经从母版复制好了（`references/production.md` 第一节）。**这个顺序不能反**——音频要落进 `<工程>/public/voice/`，工程还不存在，音频就没地方落。

## 第 0 步：视频简报（七问，开工前必答）

七个问题答完再动笔。答不出来的那一问，就是这条片子还没想清楚的地方。

```markdown
# 视频简报
- 这条给谁看？
- 陌生人为什么要看完？
- 前 3 秒的钩子是什么？
- 谁会转给谁？为什么转？（命中哪种转发动机）
- 故事来源 = 亲历 / 转述改编 / 虚构？标识怎么做？
- 画面里有哪些具体的物？
- 最后希望观众做什么？
```

最后一问有个硬核查：**可以要观点，不可以要祝福。**

| 写法 | 判定 |
|---|---|
| 「你家也有这样的亲戚吗？A 有 B 没有」 | ✅ 给了讨论理由 |
| 「给老人点个赞祝她健康」 | ❌ 拿故事换点赞，多数平台明文禁止 |
| 「转发保平安」「不转不是中国人」 | ❌ 同上，且更重 |

结尾用选择题引导评论，比开放式提问更容易有人接话。

## 篇幅

**1 分钟左右是起步锚，不是硬上限。故事讲完就停，不许为凑时长注水。** 注水直接伤完播率。

另一头也别走极端：太短的片子在有些平台够不到原创声明的门槛，发布前查一下你那个平台的最低时长。

## 一、按说话人成段，不是逐句

`script.json` 的基本单位是 **run**（一段），一个说话人连续说的话＝一段＝一次 TTS 请求。

为什么不是别的两种切法：

- **整条一次合成**：一句念坏就整条重来。时长噪声也大得多。
- **逐句合成**：模型看不见上下文，情感连不上，听着像一句一句拼出来的。
- **按说话人成段**：模型看得见整段（情感连贯就是从这儿来的），段与段之间又是独立的——**坏哪段补哪段**，其余字节不动。

重抽一段的成本是几厘钱，重抽整条是几分钱。差价不大，差在**你不敢改**。

## 二、停顿分两层，分开控制

| 层 | 写法 | 行为 |
|---|---|---|
| **段内**停顿 | 在文本里插 `<#x#>` | 交给模型 |
| **段间**停顿 | run 上的 `gap_after`（毫秒） | 拼接静音，误差为零 |

⚠️ **`<#x#>` 是「在自然停顿之上叠加」，不是「设定为」。** 实测 `实际间隔 ≈ 430ms + 1000×x`：不写标记大约 430ms，写 `<#0.5#>` 大约 930ms，写 `<#1.0#>` 大约 1443ms。**想要 550ms 就写 `<#0.12#>`。**

写完先算一遍再合成，别照字面值理解——照字面值写，出来的停顿会比你想的长近一倍。

## 三、字幕层和音频层是两回事

**句子是音频的单位，字幕行是阅读的单位。** 对戏必然产生短句，直接拿句子当字幕行，短的那些根本读不完。

合成脚本会把相邻的句子合并成够长的**行**，行的显示时长 = 下一行起点减本行起点（段间静音也算进阅读时间）。下限读 `studio.config.json` 的 `captions.minLineSeconds`，**缺省 2.5s**；受众读得快可以下调到 2.0s，年长受众上调到 3s。

🔴 **短句的音频不许改。** 一个字的回答「怕。」音频只有 0.39 秒，力量就在短促——为了让它的字幕卡够到下限，去把它后面的停顿从 1 秒加到 2.2 秒，那是**尾巴摇狗**，换来的是两秒多的死沉默。正确的做法是给短应答单独一条更松的下限（缺省 1.2s），动字幕，不动声音。

## 四、几条写稿铁律

- **序数词与小数值量词一律写汉字**——写「第 2 次」会被念成「第两次」。
- **多音字钉读音**：顶层 `pronunciation` 数组，格式 `词/(pin1)(yin1)`。
  - **按词钉，不按字**。同一条片子里「还回来」的 huán 和「还是」的 hái 都对，钉单字就把另一个搞坏了。
  - **只钉实错，不做预防钉**。注音块本身会诱发词内停顿——实测钉一个词能凭空多出两百多毫秒的顿挫，撤钉就归零。怕读错就交人耳验收，别先钉。
  - 钉了读音的段**必须重抽**，字典只对新请求生效，改不了磁盘上已经存在的音频。
- **假音色 ID 会直接报错**（`voice id not exist`），不会静默换个人给你念完。拼错当场炸，这是好事。

## 五、体检、合成、补抽

下面四条都在**项目根**下敲，`$SKILL_DIR` ＝ 本包安装目录（见 `SKILL.md`「路径约定」）：

```bash
# 读法体检：免费、不调 API、有问题退出码非 0
node $SKILL_DIR/scripts/minimax-tts.js --check <工程>/script.json

# 合成 → public/voice/narration.wav + timeline.json
node $SKILL_DIR/scripts/minimax-tts.js <工程>/script.json -o <工程>/public

# 只重抽某一段，其余字节不动
node $SKILL_DIR/scripts/minimax-tts.js <工程>/script.json -o <工程>/public --only R3

# 只拼装不合成（改停顿表 / 改字幕合并 / 改 fps 走这条）
node $SKILL_DIR/scripts/minimax-tts.js <工程>/script.json -o <工程>/public --assemble
```

**合成完即冻结。** TTS 是抽卡的：同一段文字、同样的参数，每次出来的时长都不一样（实测波动十几个百分点）。而全片的帧号都挂在 `timeline.json` 这张帧表上。所以：

- 帧号一律写成 `T.lines[n].start_frame ± 偏移` 或 `T.total_frames ± 偏移` 的表达式，**代码和 SPEC 里禁止硬编码帧数**；
- `public/voice/` 已经有音频就直接用，别重新合成；
- **改帧表 ≠ 换片子**——调停顿、调字幕合并走 `--assemble`。

## 六、审完才许合成

**顺序不能反。** 稿子写完先审，审过了再合成。合成之后再改稿，等于重抽 + 帧表连锁回写；合成之前改稿是免费的。

两个动作都要做，缺一不可：

**动作一：对照下面八条逐条报命中数。** 只写「已过」不作数，要写「第 1 条命中 2 处、第 3 条命中 1 处」这种。

1. **框架词**：删掉「首先 / 其次 / 最后」「总而言之」「值得一提的是」「不得不说」。
2. **AI 高频词**：禁用赋能、闭环、抓手、颗粒度、底层逻辑、干货满满、极致、拉满。
3. **排比与对仗**：不追求工整对仗；连续两处以上排比必拆一处。
4. **句长**：段内句子长短要错落；连续三句同构必改。
5. **情感**：至少一处真实情绪（意外、犹豫、吐槽、自嘲），至少一处个人判断。**但不许煽情**。
6. **细节**：每段至少一个具体的物（物件、数字、场景）；抽象形容词连用两个以上必删一个。
7. **口语化**：书面连接词改口头表达。每句默读自问「这话我会不会当面对朋友说」，不会说就改写。
8. **终检**：通读全文，任何「删掉也不影响」的句子直接删。

**动作二：整稿默读一遍口播。** 当面对朋友不会那么说的句子改写。书面连接词、成串同构的短句、一口气念不下来的赶稿感，都算不通畅。

**旁白是给耳朵的，不是给眼睛的。** 写得漂亮和念得顺是两件事，只有默读能分辨。

机器可判的读法问题（多音字、数字读法）由 `--check` 兜底，**它不替代人审**。

## 七、写作提醒

- **具体压倒抽象**：给细节、给物件、给对话，少用形容词。「她把攒的鸡蛋往我包里塞」比「亲情深厚」强一百倍。
- **不许煽情**。故事的力量来自克制——让观众自己哭，别在画面上写「泪目」。
- **每条必须命中一种转发动机**，写进简报，发布后回收哪种动机真的跑出了转发。

## 八、交给用户听（人工确认点②）

合成完把两样一起交出去：**旁白稿全文**（`show` 字段那一版，人读的）和**音频文件**。

然后停下来。等他说「可以」，才进 `production.md`。

他要改稿，回第一步重走，别在下游打补丁。

## 九、音频与帧表落盘格式

合成产物全部落在 `<工程>/public/voice/`。工程引擎只读其中两样：`narration.wav` 和 `timeline.json`。**没有 key 自己配音时，就照这两样的格式补齐**，其余文件是补抽用的中间件，缺了不影响渲染。

### `narration.wav` —— 旁白母带

- **一条**整片母带，不是逐句 WAV。全片的帧号都挂在它的时间轴上。
- PCM `s16le`（16 位整数）、**单声道**、采样率 32000Hz、RIFF/WAVE 容器。换参数要连 `timeline.json` 一起重算。
- 内容 = 各段 take 剪掉首尾静音后，按 `gap_after` 插入精确静音拼接而成。**段间留白是拼出来的，误差为零**，别指望在下游用帧号补。

### `timeline.json` —— 帧表 T

顶层六个键 + 一个数组，逐字如下（字段名照抄，引擎按名取值）：

| 字段 | 一句话说明 |
|---|---|
| `fps` | 帧率。全片帧号都按它换算；工程的 `Composition` 也读它 |
| `total_s` | 母带总时长，秒，三位小数 |
| `total_frames` | 母带总帧数 = `round(total_s × fps)`。尾牌接在它后面 |
| `audio` | 母带文件名，相对 `public/voice/`。固定是 `"narration.wav"` |
| `voices` | 本次**实际用到**的音色：`{说话人: 音色ID}`。记的是解析后的结果，不是稿子里写了什么 |
| `model` | 本次实际用的 TTS 模型名 |
| `lines[]` | **字幕行**数组（阅读单位，由更细的音频句合并而来）——不是音频句，也不是 run |

`lines[]` 每项五个字段：

| 字段 | 一句话说明 |
|---|---|
| `id` | 行号，`L1` 起顺排。契约测试与抽帧表都按它点名 |
| `text` | 这一行的字幕文本。**它是字幕的唯一事实源**，组件不许另抄一份 |
| `start_s` | 起始秒，三位小数，给人读的 |
| `start_frame` | 起始帧，**唯一事实源**。第一行恒为 0 |
| `dur_frames` | 本行帧数 = 下一行 `start_frame` 减本行 `start_frame`（末行减 `total_frames`）。**由相邻起始帧相减得出，不是各自独立取整**——各自取整会在帧表里留下 ±1 帧的缝 |

两条自洽约束（契约测试盯着，自己配音也必须满足）：**行与行首尾相接不许有缝**（`start_frame + dur_frames` 恰好等于下一行的 `start_frame`，末行等于 `total_frames`）；**每行停留不低于可读下限**（缺省 2.5s，≤4 字且已收口于句末标点的短应答走 1.2s，两个数读 `studio.config.json` 的 `captions`）。
