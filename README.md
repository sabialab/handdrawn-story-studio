# 手绘故事片产线（handdrawn-story-studio）

丢一两句话素材给你的 Agent，它陪你把这句话做成一条竖版手绘故事短片。

从选题候选开始，到旁白稿、配音、分镜、出片执行单、发布前自查，全程有一份写死的规范在管着。中间只留两处需要你本人点头：选哪条故事、旁白听着行不行。

这是我们自己每天真实在跑的产线，直接打包出来的。

## 装它之前：两样自备件

**这两样都要花钱，而且本 Skill 不代付、不代跑。** 先确认了再往下看。

| 自备件 | 用来干什么 | 没有会怎样 |
|---|---|---|
| **MiniMax API key** | 旁白配音（TTS）。BGM 生成是可选件，用同一个 key | 旁白稿照给你，配音自己找工具做 |
| **ChatGPT 桌面端的 Codex** | 拿着分镜执行单生图、拆图层、改工程常量、渲染出片 | 分镜和执行单照给你，换任何能跑 Remotion 的 Agent 干 |

Skill 本身开源免费（MIT）。

另外需要本机有 Node.js 与 Python 3——出片工程是 Remotion，图层处理脚本是 Python。

## 怎么装

最省事的办法是把这件事交给你的 Agent：对它说一句「帮我装 handdrawn-story-studio 这个 Skill」，要敲的命令它自己会跑。

想自己动手也行，三个入口挑一个：

- **装进已有项目**：把 `handdrawn-story-studio` 整个目录放进项目的 `.claude/skills/` 下（或者你的 Agent 存放 Skill 的地方）。GitHub 上的仓库名就是这个。
- **从 RedSkill 商店装**：搜「手绘故事片产线」，点「去使用」。
- **clone 下来直接当项目根**：`git clone` 之后就在仓库目录里开工，不必再套一层项目。

### 两种布局，一个词的差别

后面所有命令里的 **`$SKILL_DIR` ＝ 本包所在的目录**：

| 布局 | `$SKILL_DIR` 是 | 你的项目根是 |
|---|---|---|
| 装进已有项目 | `<项目根>/.claude/skills/handdrawn-story-studio/` | 你原来那个项目 |
| clone 下来当项目根 | 仓库目录本身 | 同一个仓库目录 |

**工作目录始终是项目根**，不是包目录——`handdrawn-studio/`（配置和草稿）与 `video-template/<每片工程>` 都长在项目根下。两种布局照抄同一套命令即可。

装完把 key 放进**项目根**的 `.env`：

```
MINIMAX_API_KEY=你的key
```

合成脚本按 `MINIMAX_API_KEY` 环境变量 → 项目根 `.env` → 包根 `.env` 三层依次找，三层都没有才报错。

出片工程是从母版复制出来的，复制之后在**新工程目录**里装依赖、拉一次字库（都是幂等的，跑几遍都一样）：

```bash
cp -R $SKILL_DIR/video-template/handdrawn-master video-template/<新片 slug>
cd video-template/<新片 slug>
npm install
tools/fetch_fonts.sh
```

字库落在项目根的 `video-template/assets/fonts`，同一个项目里的各片工程共用它。

## 首跑会发生什么

第一次用，Agent 会先跟你做一次定位访谈，问这些：

- 你这个号做什么内容，给谁看
- 账号名叫什么（会印在每条片子的角标上）
- 故事主要从哪来——你自己的经历、家人朋友讲的、还是你编的
- 打算多久更一条
- 发到哪个平台，画幅要什么比例
- 有没有哪类题材是你永远不碰的

答完它会写两个文件到你的项目里：`handdrawn-studio/editorial.md`（人读的）和 `handdrawn-studio/studio.config.json`（机器读的）。

**访谈只做一次**，以后每天开工都直接读这两个文件。想改定位就直接改 `editorial.md`，不用重新访谈。

## 每天怎么用

给它一两句话就行。比如：

> 我奶奶把每个塑料袋都叠成小三角，攒了一抽屉。我以前老笑她。

它会给你 3 个候选，每个都标好这条故事算亲历还是虚构、谁会把它转给谁、五个维度各打了几分。你挑一个，或者全否了让它重来。

挑完它写旁白稿、合成配音，然后停下来等你听。听着行，它才出分镜 SPEC 和给 Codex 的执行单。

你把执行单丢给 ChatGPT 桌面端的 Codex，Codex 按单生图、渲染、自检，把成片交回来。Agent 抽帧读图核一遍（错字、字号、安全区、演绎标识），再走一遍发布前自查清单，最后把标题、描述、封面、母带一起摆给你。

完整的一次跑法见 [examples/demo-run.md](examples/demo-run.md)。

## 出片这一段为什么要 Codex

生图、拆图层、改工程常量、渲染、自检——这一整段是体力活，交给一个能读写工作区、能自己跑命令的执行体最省事。我们用的是 ChatGPT 桌面端的 Codex，所以执行单是照它的习惯写的。

换别的执行体也能跑：执行单是一份纯文本的活儿清单，里面写清了每张图画什么、验收阈值多少、改哪个文件的哪个常量。母版工程自带 `tools/verify.sh`，本机渲染那条路一直是通的。

**Agent 不会去驱动你的桌面端。** 它只交两样东西：配音音频和执行单，剩下的你自己安排。

## FAQ

**收费吗？**
Skill 免费，MIT 协议。花钱的是 MiniMax 的 TTS 调用和你的 ChatGPT 订阅，那两个是你自己的账号。一条一分钟左右的片子，TTS 大概几分钱。

**能保证涨粉吗？**
不能，本 Skill 不承诺任何数据效果。它管的是「把一句话变成一条能发的片子」这段流程，以及发布前别踩坑。

**编的故事能做吗？**
能，但必须标演绎，绝不打「真实故事」类标签。这条写死在规范里，Agent 每条片子都会核。判据是「观众会不会以为这是你本人的真事」——虚构故事用第一人称讲，就必须标。

**我的受众不是你们的受众，字号和字幕节奏合适吗？**
那几个数是缺省值，不是铁律。字幕行停留、字号下限都在配置里，访谈时会问你受众情况，之后你随时能改。

**没有 MiniMax key 能用吗？**
能用到旁白稿这一步。Agent 会把稿子和停顿标记一起交给你，你拿去任何 TTS 工具合成，再按格式把音频放回工程。

**片子有多长？**
一分钟左右是起步锚，不是硬上限。故事讲完就停，不为凑时长注水。

## v1 没做的事

写在这里是为了别让你以为它们已经在包里了。

- **日历预案**：节日、节气、季节提前进选题的自动提醒。逻辑不难，但节气和农历的日期得逐年联网核准，凭模型现算必错，这份数据源还没做进来。
- **评论区挖忠告**：从对标账号评论区批量捞「可以送人的那句话」。它依赖付费的第三方数据接口，不想让整个包背上这个依赖。
- **周报与 A/B 判定**：按周回收数据、机器算派生指标、判两组内容谁跑得好。这一段跟平台的数据接口绑得很死，各家不一样，先不做。
- **机器发布守门**：把发布前自查做成一个脚本跑出 0 ERROR。现有的守门脚本跟我们自己的仓库结构绑死了，搬过来会水土不服，v1 先用 `references/publish-check.md` 的人工清单顶着。
- **BGM 与音效不随包带**：母版的 `public/audio/`（`bgm.mp3` / `page.mp3` / `tap.mp3`）是空的——音频授权各家条款不同，替你选一份塞进包里是给你埋雷。自己备三个文件放进去即可；`scripts/minimax-music.js` 能用同一把 MiniMax key 生成 BGM，但那是可选件。**暂时不想要 BGM 和音效的话，现在得自己动手**：删掉 `src/AudioMix.tsx` 里对应的那几条 `<Audio>` 轨，或者拿静音文件占位（`tools/probe.sh` 渲静帧时就是这么造占位的）。v1 没做「一键无 BGM」的开关。
- **只有 9:16 一个画幅**：3:4、16:9 都没落地。`LAYOUT` 特意保留了 `portrait` 这个键名、`Fx.tsx` 的 `useStoryLayout()` 特意留了分支接缝，但真要加画幅，安全区、字幕位、舞台尺寸、钩子字号那几个咬合的数都得重算一遍——这不是加一行配置的事。
- **查重没有台账**：`references/daily-flow.md` 第 3 步要求按「情景 + 冲突 + 结局」三元组比对近 30 天，但包里没有存这份历史的文件，也没有查重脚本——现在靠你自己的 `handdrawn-studio/drafts/` 目录和记性。发得多了要自己建一份台账。
- **示例的场景数与母版对不上**：`examples/demo-run.md` 讲的是 34 秒拆 9 张画，母版工程 `SCENE_ART` 只落了 3 个场景（对应示例旁白的 3 段说话人切换）。**母版是骨架不是成片**：场景数跟着你自己旁白稿的切换点走，加场景照 `Scenes.tsx` 末尾那个级联模式续写。密度基线（一分钟 ≥9 张）以 `references/production.md` 第 4.1 节为准。
